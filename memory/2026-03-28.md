## 附件上传 API 调试经验（2026-03-28 晚）

**问题：**
调用 `https://open.feishu.cn/open-apis/drive/v1/files/upload_all` 上传图片到 bitable 附件字段，API 始终返回 `code: 1061002 params error`。

**根本原因：**
Node.js  Buffer 拼接 multipart body 时，二进制文件内容长度计算不准。代码：
```
Buffer.concat([headerBuf, fileBuf, trailerBuf])
```
而 `Content-Length` header 提前用 `Buffer.byteLength(body)` 计算，但 body 里的 `\r\n` 等于 2 字节，实际拼接后有细微差异。

**最终解决方案（Node.js）：**
```javascript
const headerBuf = Buffer.from(headerString, 'utf-8');
const fileBuf = fs.readFileSync(filePath);
const trailerBuf = Buffer.from(trailerString, 'utf-8');
const totalLen = headerBuf.length + fileBuf.length + trailerBuf.length;
// 拼 Buffer 时也要用 Buffer.concat
const fullBody = Buffer.concat([headerBuf, fileBuf, trailerBuf]);
```
关键点：
1. 先把 header 和 trailer 转成 Buffer，再和文件 Buffer 拼接
2. 总长度分别计算后求和
3. 不要用字符串拼接方式算 Content-Length

**已验证成功的参数组合：**
```
file_name: "xxx.jpg"
file_type: "image"
parent_type: "bitable_image"
parent_node: {app_token}
size: {文件字节数}
extra: {"bitablePerm":{"tableId":"...","fieldId":"...","recordId":"..."}}
file: [二进制文件内容]
Content-Type: multipart/form-data; boundary=...
Content-Length: {totalLen}
```

**教训：**
- multipart/form-data 的 Content-Length 必须和实际发送的 body 字节数完全一致
- 二进制文件部分不能先转字符串再拼接，会破坏数据
- 飞书 API 的 params error 有时是 Content-Length 不匹配，不是参数本身问题
